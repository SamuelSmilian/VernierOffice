# Development Contract

## Objective

Complete the assigned task by following the repository specifications.

The repository documentation is the single source of truth.

Never replace missing specifications with assumptions.

---

## Initialization

Before making any changes:

1. Read every Markdown document in the repository.
2. Build a complete understanding of the project.
3. Identify the current development stage.
4. Report any conflicting or missing specifications.

Do not begin implementation until the project context is complete.

---

## Development Process

Always work in the following order:

Understand

↓

Plan

↓

Implement

↓

Document

↓

Test

↓

Verify

Complete one task before starting the next.

---

## Planning Phase

During planning:

- Improve planning documents whenever a simpler design is found.
- Remove unnecessary complexity.
- Prefer consistency over new features.

Planning documents may evolve freely.

---

## Implementation Phase

Once implementation begins:

- Treat project specifications as frozen.
- Do not redesign the language.
- Do not change the architecture.
- Record design issues instead of fixing them immediately.

Implement only what is specified.

---

## Working Rules

Always:

- Keep the implementation simple.
- Prefer semantic consistency.
- Keep modules independent.
- Write deterministic code.
- Keep documentation synchronized with implementation.
- Keep examples synchronized with implementation.
- Keep tests synchronized with implementation.

Never:

- Guess specifications.
- Introduce speculative features.
- Add unnecessary abstractions.
- Skip documentation.
- Skip examples.
- Skip tests.

---

## Deliverables

Every completed feature must include:

- Source code
- Documentation
- Examples
- Tests

Documentation should describe behaviour rather than implementation.

Examples should compile successfully.

Tests should verify all public behaviour.

---

## Verification

Before completing a task:

1. Run all available tests.
2. Verify examples.
3. Verify documentation.
4. Summarise completed work.
5. Report unresolved issues.

Never claim a feature is complete without verification.
