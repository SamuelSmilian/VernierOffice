# Feature Inventory

## Document Structure

### Section / Chapter

- **Purpose**: Hierarchical division of a document into major parts.
- **Office**: Sections via `w:sectPr` in OOXML. No native chapter concept.
- **LaTeX**: `\chapter{}`, `\section{}`, `\subsection{}`, `\subsubsection{}`.
- **Existing Solution**: Typst — `= Heading`, `== Heading`. HTML — `<h1>`–`<h6>`, `<section>`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Section nesting conveys document hierarchy. The language should support heading levels generically rather than prescribing chapter/part semantics.

### Paragraph

- **Purpose**: The fundamental block of prose text.
- **Office**: `w:p` in OOXML.
- **LaTeX**: Implicit — blank line or `\par`.
- **Existing Solution**: HTML — `<p>`. Typst — blank line.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: The basic unit of text. Must support inline content.

### Title / Document Title

- **Purpose**: The top-level title of the entire document.
- **Office**: Document properties (`dc:title`) and styled paragraph.
- **LaTeX**: `\title{}` + `\maketitle`.
- **Existing Solution**: HTML — `<title>`. Typst — `#set document(title: ...)`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Distinct from section headings. A document-level property.

### Abstract

- **Purpose**: A summary of the document content, typically placed after the title.
- **Office**: Styled paragraph, no native element.
- **LaTeX**: `\begin{abstract}...\end{abstract}`.
- **Existing Solution**: HTML — no native element.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Common in academic and technical documents.

### Table of Contents

- **Purpose**: Auto-generated list of document sections with page references.
- **Office**: `w:sdt` with TOC field code.
- **LaTeX**: `\tableofcontents`.
- **Existing Solution**: Typst — `#outline`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Derived from heading structure. Generated by the backend.

### Appendix

- **Purpose**: Supplementary content placed after the main body.
- **Office**: Styled section, no native concept.
- **LaTeX**: `\appendix` + `\section{}`.
- **Existing Solution**: HTML — no native concept.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Changes heading numbering style. Useful for reports and academic documents.

### Page Break

- **Purpose**: Force content to start on a new page.
- **Office**: `w:br` with type "page".
- **LaTeX**: `\newpage`, `\pagebreak`.
- **Existing Solution**: HTML — `page-break-before` in CSS. Typst — `#pagebreak()`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Page breaks are layout decisions, not semantic ones. Should be handled via backend styling rules, not language syntax.

### Column Layout

- **Purpose**: Multi-column text flow.
- **Office**: `w:cols` in section properties.
- **LaTeX**: `\twocolumn`, `multicol` package.
- **Existing Solution**: HTML — CSS `column-count`. Typst — `#set page(columns: 2)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Layout concern. Backend styling rules, not language semantics.

### Header / Footer

- **Purpose**: Repeated content at the top or bottom of each page.
- **Office**: `w:headerReference`, `w:footerReference`.
- **LaTeX**: `\pagestyle{}`, `fancyhdr` package.
- **Existing Solution**: HTML — CSS `@page` with `@top-center` etc. Typst — `#set page(header: ...)`.
- **Classification**: Mixed
- **Decision**: Backend Only
- **Notes**: Content is often derived from metadata (page number, chapter title). Semantic, but best handled as backend templates with metadata references.

### Page Number

- **Purpose**: Sequential page numbering.
- **Office**: PAGE field code in header/footer.
- **LaTeX**: `\pagenumbering{}`, `\thepage`.
- **Existing Solution**: Typst — `#counter(page).display()`.
- **Classification**: Implementation
- **Decision**: Backend Only
- **Notes**: Automatically generated by all backends. No language syntax needed.

## Text

### Emphasis (Bold / Italic)

- **Purpose**: Mark text as having increased importance or stress.
- **Office**: `w:b`, `w:i` on run properties.
- **LaTeX**: `\textbf{}`, `\textit{}`, `\emph{}`.
- **Existing Solution**: HTML — `<strong>`, `<em>`. Typst — `#strong()`, `#emph()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: `\emph{}` is semantic (context-dependent); bold/italic are presentation. The language should provide a single `emphasis` construct rather than bold/italic separately. Nesting levels can map to different presentations per backend. This follows the CSS/HTML model where `<em>` nests to indicate increasing emphasis.

### Underline

- **Purpose**: Mark text with a line underneath.
- **Office**: `w:u` on run properties.
- **LaTeX**: `\underline{}`, `ulem` package.
- **Existing Solution**: HTML — `<u>` (now semantic for unarticulated annotations). Typst — `#underline()`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Primarily visual. In Office, underlining is used for misspellings, links, and emphasis — each has its own semantic construct. No need for a language-level underline.

### Strikethrough

- **Purpose**: Mark text as deleted or no longer relevant.
- **Office**: `w:strike` on run properties.
- **LaTeX**: `\sout{}` from `ulem`.
- **Existing Solution**: HTML — `<del>`, `<s>`. Typst — `#strike()`.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: `<del>` carries semantic meaning (deletion). `<s>` is presentational (no longer accurate). Useful for revision tracking but overlaps with track changes.

### Subscript / Superscript

- **Purpose**: Text lowered or raised relative to the baseline.
- **Office**: `w:vertAlign` with "subscript" or "superscript".
- **LaTeX**: `_{}`, `^{}` in math mode; `\textsubscript{}`, `\textsuperscript{}` in text mode.
- **Existing Solution**: HTML — `<sub>`, `<sup>`. Typst — `#sub()`, `#super()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Carries meaning (chemical formulas, footnotes, exponents, ordinals). Core regardless of math mode.

### Hyperlink

- **Purpose**: A navigable reference to an external resource or internal location.
- **Office**: `w:hyperlink` with `r:id` target.
- **LaTeX**: `\href{}{}`, `\url{}` from `hyperref`.
- **Existing Solution**: HTML — `<a href="">`. Typst — `#link("")[]`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Fundamental to digital documents. Must support both external URLs and internal cross-references.

### Line Break

- **Purpose**: Force text to break to the next line within a paragraph.
- **Office**: `w:br`.
- **LaTeX**: `\\`, `\newline`.
- **Existing Solution**: HTML — `<br>`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Line breaking is layout-driven. Occasional semantic need (poetry, addresses) can be handled by a dedicated block type rather than an inline break.

### Font Family / Size / Color

- **Purpose**: Control the visual appearance of text.
- **Office**: `w:rFonts`, `w:sz`, `w:color` on run properties.
- **LaTeX**: `\textrm{}`, `\textsf{}`, `\texttt{}`, `\fontsize{}`, `\textcolor{}`.
- **Existing Solution**: HTML — CSS `font-family`, `font-size`, `color`. Typst — `#text(font: ..., size: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Pure presentation. Belongs in backend style sheets, not the semantic language.

### Small Caps

- **Purpose**: Uppercase glyphs at lowercase height.
- **Office**: `w:smallCaps` on run properties.
- **LaTeX**: `\textsc{}`.
- **Existing Solution**: HTML — `font-variant: small-caps` in CSS. Typst — `#smallcaps()`.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Bordering on presentation, but small caps carry semantic weight for acronyms, proper names, and bibliographic entries in many style guides.

### Highlight

- **Purpose**: Mark text with a background color for attention.
- **Office**: `w:highlight` on run properties.
- **LaTeX**: `\hl{}` from `soul`. No native support.
- **Existing Solution**: HTML — `<mark>`. Typst — `#highlight()`.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: `<mark>` implies relevance to the reader. Distinct from general background coloring which is purely presentational.

### Code / Monospace

- **Purpose**: Inline text representing code, commands, or literal input/output.
- **Office**: Styled run with monospace font. No native element.
- **LaTeX**: `\texttt{}`, `\verb|...|`.
- **Existing Solution**: HTML — `<code>`, `<kbd>`, `<samp>`. Typst — `#raw()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Common in technical documents. Semantically distinct from general monospace formatting.

## Layout

### Page Size

- **Purpose**: Physical dimensions of the output page.
- **Office**: `w:pgSz` in section properties.
- **LaTeX**: `\usepackage[paperwidth=,paperheight=]{geometry}`.
- **Existing Solution**: Typst — `#set page(width: ..., height: ...)`. HTML — `@page { size: }` in CSS.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Does not affect document meaning. Belongs in backend configuration.

### Page Margins

- **Purpose**: Blank space around page content.
- **Office**: `w:pgMar` in section properties.
- **LaTeX**: `\usepackage[margin=]{geometry}`.
- **Existing Solution**: Typst — `#set page(margin: ...)`. HTML — `@page { margin: }` in CSS.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Purely presentational. Backend configuration.

### Text Alignment

- **Purpose**: Horizontal positioning of text within its container.
- **Office**: `w:jc` on paragraph properties.
- **LaTeX**: `\raggedright`, `\raggedleft`, `\centering`, `\justify`.
- **Existing Solution**: HTML — `text-align` in CSS. Typst — `#align()`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Alignment is visual. Exceptions like poetry (left-aligned by convention) are handled by block types, not alignment properties.

### Indentation

- **Purpose**: Horizontal offset of the first line or entire paragraph.
- **Office**: `w:ind` on paragraph properties.
- **LaTeX**: `\parindent`, `\hangindent`, `\leftskip`, `\rightskip`.
- **Existing Solution**: HTML — `text-indent`, `margin-left` in CSS. Typst — `#par(first-line-indent: ...)`.
- **Classification**: Mixed
- **Decision**: Backend Only
- **Notes**: First-line indent carries semantic weight (paragraph separation in many traditions). However, this is typically a global style decision, not per-paragraph semantics.

### Line Spacing

- **Purpose**: Vertical space between lines of text.
- **Office**: `w:spacing` on paragraph properties.
- **LaTeX**: `\linespread{}`, `\setstretch{}` from `setspace`.
- **Existing Solution**: HTML — `line-height` in CSS. Typst — `#set par(leading: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Visual preference. No semantic meaning.

### Paragraph Spacing

- **Purpose**: Vertical space before and after paragraphs.
- **Office**: `w:spacing` with `w:before`, `w:after`.
- **LaTeX**: `\parskip`, `\setlength{\parskip}{}`.
- **Existing Solution**: HTML — `margin-top`, `margin-bottom` in CSS. Typst — `#set par(spacing: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Visual preference. No semantic meaning.

### Widow / Orphan Control

- **Purpose**: Prevent single lines of a paragraph from being isolated at page boundaries.
- **Office**: `w:widowControl` on paragraph properties.
- **LaTeX**: `\widowpenalty`, `\clubpenalty`.
- **Existing Solution**: Typst — handled automatically. HTML — `orphans`, `widows` in CSS.
- **Classification**: Implementation
- **Decision**: Backend Only
- **Notes**: Typesetting quality concern. Backend responsibility.

## Style

### Named Styles

- **Purpose**: Reusable, named collections of formatting properties applied to document elements.
- **Office**: Styles defined in `w:styles` (`w:style`). Core to the Office model.
- **LaTeX**: `\newenvironment{}`, `\newtheorem{}`, `\newcommand{}` for macro-based reuse.
- **Existing Solution**: HTML — CSS classes. Typst — `#let` + `#set` + `#show` rules.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Named styles abstract presentation from content. "Heading 1" is semantic; its font size is not. Styles are the primary mechanism for backend-driven presentation.

### Style Inheritance

- **Purpose**: A style derives properties from a parent style and overrides specific ones.
- **Office**: `w:basedOn` in style definition.
- **LaTeX**: Not native; approximated through macro composition.
- **Existing Solution**: CSS — cascade and inheritance. Typst — `#set` rules with scoping.
- **Classification**: Implementation
- **Decision**: Backend Only
- **Notes**: Useful for backend implementations but not a language-level concern.

### Character Style vs Paragraph Style

- **Purpose**: Distinguish between styles applied to text spans and styles applied to block elements.
- **Office**: `w:style` with `w:type` = "paragraph" or "character".
- **LaTeX**: Commands for inline (`\textbf`) vs environment for block.
- **Existing Solution**: HTML — inline elements vs block elements. CSS — inline vs block display.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Fundamental distinction. The language must differentiate inline formatting from block-level constructs.

### Themes

- **Purpose**: A coordinated set of fonts, colors, and effects applied globally.
- **Office**: `a:theme` in OOXML (fonts, colors, effects).
- **LaTeX**: No native equivalent; approximated through package options and preamble configuration.
- **Existing Solution**: CSS — custom properties and design tokens. Typst — not native.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Pure presentation. Backend configuration through style sheets.

## Tables

### Table

- **Purpose**: A two-dimensional arrangement of data in rows and columns.
- **Office**: `w:tbl` in OOXML.
- **LaTeX**: `tabular`, `tabularx`, `tabulary` environments.
- **Existing Solution**: HTML — `<table>`. Typst — `#table()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: One of the most important document constructs. Must support headers, data cells, and captions.

### Table Row

- **Purpose**: A horizontal group of cells in a table.
- **Office**: `w:tr` in OOXML.
- **LaTeX**: Implicit — `\\` in `tabular`.
- **Existing Solution**: HTML — `<tr>`. Typst — implicit in `#table()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Structural element. May carry row-level properties like header row designation.

### Table Cell

- **Purpose**: A single data container at a row-column intersection.
- **Office**: `w:tc` in OOXML.
- **LaTeX**: Implicit — `&` separated content in `tabular`.
- **Existing Solution**: HTML — `<td>`, `<th>`. Typst — array element in `#table()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Distinction between header cells and data cells is semantic.

### Merged Cells

- **Purpose**: A cell that spans multiple rows or columns.
- **Office**: `w:gridSpan`, `w:vMerge` in OOXML.
- **LaTeX**: `\multicolumn{}{}{}`, `\multirow{}{}{}` from `multirow` package.
- **Existing Solution**: HTML — `colspan`, `rowspan` attributes. Typst — `#table.cell(colspan: ..., rowspan: ...)`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Carries meaning about data relationships. A cell spanning columns represents a value that applies to multiple categories.

### Table Caption

- **Purpose**: A label and description for a table.
- **Office**: Styled paragraph before or after the table. No native caption element.
- **LaTeX**: `\caption{}` inside `table` environment.
- **Existing Solution**: HTML — `<caption>`. Typst — `#figure()` with `kind: "table"`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Associates descriptive text with the table. Essential for cross-referencing and accessibility.

### Table Borders / Grid Lines

- **Purpose**: Visual lines separating table cells.
- **Office**: `w:tblBorders`, `w:tcBorders` in OOXML.
- **LaTeX**: `\hline`, `\cline{}{}`, `booktabs` package rules.
- **Existing Solution**: HTML — CSS `border`. Typst — `#table(stroke: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Borders are visual. The semantic content is the cell relationships, not the lines between them. Backends apply default grid styles.

### Table Column Width

- **Purpose**: The horizontal size of a table column.
- **Office**: `w:gridCol` with `w:w` in OOXML.
- **LaTeX**: `p{}`, `m{}`, `b{}` column specifiers. `tabularx` for proportional widths.
- **Existing Solution**: HTML — CSS `width`, `<colgroup>`. Typst — `#table(columns: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Width is layout, not semantics. Backends determine column widths from content or configuration.

## Figures

### Image

- **Purpose**: A visual element embedded in the document.
- **Office**: `w:drawing` referencing an image relationship.
- **LaTeX**: `\includegraphics{}` from `graphicx`.
- **Existing Solution**: HTML — `<img>`. Typst — `#image()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: References an external image file. The language should describe what the image is, not how it is rendered.

### Figure Caption

- **Purpose**: A label and description for a figure.
- **Office**: Styled paragraph near the image. No native caption element.
- **LaTeX**: `\caption{}` inside `figure` environment.
- **Existing Solution**: HTML — `<figcaption>`. Typst — `#figure()` with caption.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Associates descriptive text with the figure. Essential for cross-referencing and accessibility.

### Figure (Container)

- **Purpose**: A floating or anchored container that groups an image with its caption.
- **Office**: `w:drawing` with anchor properties.
- **LaTeX**: `\begin{figure}...\end{figure}`.
- **Existing Solution**: HTML — `<figure>`. Typst — `#figure()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: A figure is a semantic unit — its content, caption, and placement intent are a single concept.

### Image Size / Scaling

- **Purpose**: Control the rendered dimensions of an image.
- **Office**: `wp:extent` on drawing.
- **LaTeX**: `\includegraphics[width=,height=,scale=]{}`.
- **Existing Solution**: HTML — `width`, `height` attributes. Typst — `#image(width: ..., height: ...)`.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Sizing is presentation. Backends apply defaults. Can be overridden through styles.

### Vector Graphics (Shapes)

- **Purpose**: Programmatic or predefined geometric shapes.
- **Office**: `w:drawing` with DrawingML shapes.
- **LaTeX**: `TikZ`, `PGF` for programmatic drawing.
- **Existing Solution**: HTML — `<svg>`, `<canvas>`. Typst — `#path()`, `#rect()` etc.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Shapes are decorative or diagrammatic. A dedicated diagramming construct (e.g., via a chart/diagram category) would be preferable to generic shape drawing.

### Image Placement / Float

- **Purpose**: Control whether an image is fixed in the text flow or floats to a position.
- **Office**: `wp:positionH`, `wp:positionV` on drawing.
- **LaTeX**: Float placement specifiers `[htbp]`, `\centering`.
- **Existing Solution**: HTML — `float` in CSS. Typst — `#figure()` placement.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Float placement is a layout algorithm concern. The semantic intent ("this figure belongs with this text") is captured by the figure's position in the source.

## Charts

### Chart Data

- **Purpose**: The underlying data values that a chart represents.
- **Office**: `c:chart` with embedded `c:externalData` or worksheet reference.
- **LaTeX**: No native support. `pgfplots` reads data from tables or external files.
- **Existing Solution**: HTML — data attributes or JavaScript data binding. Typst — no native chart support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: The data is semantic; the visual representation is not. The language could describe chart data and let backends render it.

### Chart Type

- **Purpose**: The visual form of a chart (bar, line, pie, scatter, etc.).
- **Office**: `c:barChart`, `c:lineChart`, `c:pieChart` etc. in OOXML.
- **LaTeX**: `pgfplots` — `\addplot` with style options.
- **Existing Solution**: HTML — JavaScript chart libraries. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Chart type conveys meaning (comparison, trend, proportion). The semantic choice of chart type should be in the language, not the rendering details.

### Chart Styling (Colors, Grid, Legend)

- **Purpose**: Visual appearance of chart elements.
- **Office**: `c:chartSpace` with color, gridline, and legend formatting.
- **LaTeX**: `pgfplots` style options.
- **Existing Solution**: HTML — CSS/chart library configuration.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Pure presentation. Backends provide default chart styles.

### Chart Title / Axis Labels

- **Purpose**: Text labels describing the chart and its axes.
- **Office**: `c:title`, `c:catAx`/`c:valAx` with `c:title`.
- **LaTeX**: `pgfplots` — `\addplot` with `title`, `xlabel`, `ylabel`.
- **Existing Solution**: HTML — chart library configuration.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Labels carry semantic meaning about what the chart represents. In scope if charts are in scope.

## References

### Cross-Reference

- **Purpose**: A reference to another location within the document (section, figure, table).
- **Office**: REF field code referencing a bookmark or caption.
- **LaTeX**: `\label{}` + `\ref{}`, `\autoref{}`, `\cref{}` from `cleveref`.
- **Existing Solution**: HTML — `<a href="#id">`. Typst — `#ref()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Fundamental to non-linear document reading. Must resolve to the correct label text and number.

### Citation

- **Purpose**: A reference to an external source, typically keyed to a bibliography entry.
- **Office**: CITATION field code. Limited native support.
- **LaTeX**: `\cite{}`, `\parencite{}` from `biblatex`.
- **Existing Solution**: HTML — `<cite>`. Typst — `#cite()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Essential for academic and technical documents.

### Bibliography / Reference List

- **Purpose**: A list of cited works, typically at the end of the document.
- **Office**: No native bibliography element. Approximated with fields and structured paragraphs.
- **LaTeX**: `\printbibliography` from `biblatex`. `\begin{thebibliography}...\end{thebibliography}`.
- **Existing Solution**: HTML — `<ol>` with structured `<cite>` entries. Typst — `#bibliography()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Generated from citations. The language should specify a bibliography source; formatting is backend responsibility.

### Footnote

- **Purpose**: An explanatory note placed at the bottom of the page, referenced from the body text.
- **Office**: `w:footnoteReference`, `w:footnote` in OOXML.
- **LaTeX**: `\footnote{}`.
- **Existing Solution**: HTML — no native element (approximated with anchors). Typst — `#footnote()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Footnotes carry semantic content — they are not merely presentational. Widely used in academic, legal, and technical writing.

### Endnote

- **Purpose**: An explanatory note collected at the end of the document or section.
- **Office**: `w:endnoteReference`, `w:endnote` in OOXML.
- **LaTeX**: `\endnote{}` from `endnotes` package.
- **Existing Solution**: HTML — approximated with links. Typst — `#footnote()` with numbering configuration.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Semantically identical to footnotes; differs only in placement. Can be handled as a footnote variant.

### Index

- **Purpose**: An alphabetized list of terms with page references.
- **Office**: XE field code for index entries, INDEX field code to generate.
- **LaTeX**: `\index{}` + `\printindex` from `makeidx`/`imakeidx`.
- **Existing Solution**: HTML — no native support. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Valuable for reference works. Requires two-pass compilation.

### Glossary / List of Terms

- **Purpose**: A list of defined terms and their definitions.
- **Office**: No native support. Approximated with structured paragraphs.
- **LaTeX**: `glossaries` package.
- **Existing Solution**: HTML — `<dl>`. Typst — `#terms()`.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: `<dl>` (description list) is a general semantic construct that covers glossaries, definition lists, and FAQs.

- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Affects hyphenation, spell-checking, and locale-specific formatting.

### Revision / Version

- **Purpose**: A document version identifier.
- **Office**: `cp:revision` in core properties.
- **LaTeX**: `\newcommand{\revision}{}`. No standard command.
- **Existing Solution**: HTML — no standard element. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Useful for document management. Low implementation cost.

## Collaboration

### Comment

- **Purpose**: An annotation attached to a specific location in the document.
- **Office**: `w:commentRangeStart`, `w:commentRangeEnd`, `w:commentReference`, `w:comment` in OOXML.
- **LaTeX**: `\todo{}` from `todonotes`. `pdfcomment` package for PDF annotations.
- **Existing Solution**: HTML — no native equivalent. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Comments carry meaning about the document's state and review process. Important for collaboration workflows.

### Track Changes / Revision Marks

- **Purpose**: Record insertions, deletions, and formatting changes with authorship.
- **Office**: `w:ins`, `w:del` with author and date in OOXML.
- **LaTeX**: `changes` package. `latexdiff` for external diffing.
- **Existing Solution**: HTML — `<ins>`, `<del>` with `cite`/`datetime`. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Carries authorship and temporal semantics. Important for review workflows but complex to implement.

### Annotation / Highlight

- **Purpose**: User-applied emphasis or marking on text for review purposes.
- **Office**: `w:highlight` with author reference.
- **LaTeX**: No native equivalent.
- **Existing Solution**: HTML — `<mark>`. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Overlaps with highlight (Text category) and comments. Consider consolidating under a general "annotation" concept.

## Presentation

### Slide

- **Purpose**: A single screen or page in a presentation.
- **Office**: `p:sld` in PresentationML.
- **LaTeX**: `\begin{frame}...\end{frame}` in Beamer.
- **Existing Solution**: HTML — `<section>` (in presentation context). Typst — slides via `#slide()` in `touying`/`polylux`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: The fundamental unit of a presentation. The same semantic model should handle both documents and presentations.

### Slide Title

- **Purpose**: The heading of a single slide.
- **Office**: `p:ph` with type "title" or "ctrTitle".
- **LaTeX**: `\frametitle{}` in Beamer.
- **Existing Solution**: HTML — `<h1>` within slide `<section>`. Typst — `#slide(title: ...)`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Maps naturally to a heading within a slide context.

### Slide Layout

- **Purpose**: A predefined arrangement of content placeholders on a slide.
- **Office**: `p:sldLayout` with `p:ph` placeholders.
- **LaTeX**: Beamer themes and column environments.
- **Existing Solution**: HTML — CSS grid/flexbox templates. Typst — `#slide()` with layout options.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: The semantic content is the structure (title + body, two-column, title only). Specific placeholder positions are presentation.

### Speaker Notes

- **Purpose**: Notes accompanying a slide, visible to the presenter but not the audience.
- **Office**: `p:notes` in PresentationML.
- **LaTeX**: `\note{}` in Beamer.
- **Existing Solution**: HTML — hidden `<div>` or `data-` attribute. Typst — no native support.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Carries presentation-specific semantic content. Important for the PPTX target.

### Incremental Reveal

- **Purpose**: Content on a slide that appears progressively during the presentation.
- **Office**: Animation effects on shapes.
- **LaTeX**: `\pause`, `\onslide<>`, `\only<>` in Beamer.
- **Existing Solution**: HTML — CSS animations triggered by slide progression. Typst — `#pause` in `polylux`.
- **Classification**: Semantic
- **Decision**: Optional
- **Notes**: Controls audience attention and information pacing. Semantic because it defines the presentation narrative structure, not just visual effects.

### Slide Transition

- **Purpose**: Animated effect when moving from one slide to the next.
- **Office**: `p:transition` in PresentationML.
- **LaTeX**: No native Beamer support (PDF limitation).
- **Existing Solution**: HTML — CSS transitions. Typst — no native support.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Pure visual effect. No semantic value. Backend default or configuration.

### Animation

- **Purpose**: Motion effects applied to slide elements.
- **Office**: `p:anim*` elements in PresentationML.
- **LaTeX**: No native Beamer support (PDF limitation).
- **Existing Solution**: HTML — CSS animations/transitions. Typst — no native support.
- **Classification**: Presentation
- **Decision**: Backend Only
- **Notes**: Pure visual effect. Backend configuration.

### List

- **Purpose**: An ordered or unordered collection of items.
- **Office**: `w:numPr` on paragraphs (numbered and bulleted lists).
- **LaTeX**: `itemize`, `enumerate`, `description` environments.
- **Existing Solution**: HTML — `<ul>`, `<ol>`, `<dl>`. Typst — `#list()`, `#enum()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Lists convey structure and meaning. Ordered vs. unordered is a semantic distinction. Description/definition lists are their own semantic construct. Placed here rather than in Document Structure because lists are especially important in presentations.

### Block Quote

- **Purpose**: An extended quotation set apart from the main text.
- **Office**: Styled paragraph. No native element.
- **LaTeX**: `quote`, `quotation`, `verse` environments.
- **Existing Solution**: HTML — `<blockquote>`. Typst — `#quote()`.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Carries clear semantic meaning (attributed quotation). Distinct from visual indentation.

### Code Block

- **Purpose**: A multi-line block of code, commands, or preformatted text.
- **Office**: Styled paragraph with monospace font. No native element.
- **LaTeX**: `verbatim`, `lstlisting` from `listings`. `minted` for syntax highlighting.
- **Existing Solution**: HTML — `<pre>`, `<code>` (block). Typst — `#raw()` with block mode.
- **Classification**: Semantic
- **Decision**: Core
- **Notes**: Different from inline code. Block-level semantics with optional language specification for syntax highlighting.
